# 同梱辞書の実装と確認方法

## 0.7.12の共通対策

固定辞書は75,542キーを維持する。`candidate-scoped-descriptions.json`は、実際の画面・段落役割・スロット情報と原文/訳文ハッシュを確認した4件の適用条件を保持する。`scripts/dictionary-observed-applicability.json`から生成し、辞書build ID・元の登録・source IDsを再検証する。別scopeの無条件検索は行わない。

`alignment.json`は81プラン。追加8件は原文と訳文のハッシュ・UTF-16範囲・語句対応を記録し、うち3件の`bodyAnchor`は本文のnative Styleを参照する。色のRGB値を固定する設定ではない。原文の同一索引に異なる本文役割があれば使わず、古いハッシュや不正な範囲も採用しない。

説明の折り返しと独立したRecipeの行は区別する。通常の全文照合を優先し、未一致の場合だけCollection/Rewardsの根拠・全行の固定訳・固有名保持・色復元・範囲の完全被覆を確認して分離する。この構造を表示、手動API要求、キャッシュ、診断で共有し、API再翻訳中も段落を切り替えない。

NPC変数は承認済みの3文だけに限定する。`localPlayerName`はクライアントの既知プロフィールから照合へ渡し、任意のユーザー名を許可しない。個人チャットはこの経路を使わない。新旧のステータス記号は旧lookupを変更せず、未一致時の別索引で候補競合と値を確認する。

共有ログは旧schemaにも対応する。新しいTooltip schema 3の`MATCHED_ORIGINAL`は取得元を特定できた原文、`UNMATCHED_DISPLAY`は取得元未確定の表示側の観測である。`STATE_SUMMARY.observationCount`は対応する`STATE_CHANGE`を含む累積値なので両者を加算しない。`displayStyledLines`は翻訳後のRGB/書式だけを記録し、nativeのclick/hover/insertionは共有しない。

`NPC_TRANSLATION_STATUS`はAPI補助経路のphase/outcomeであり、HUD表示完了を意味しない。traceは原文・話者・前会話・Styleの同一状態をまとめるIDで、受信回数やrequest IDではない。`observedAt`は状態を観測した時刻、`time`は保存時刻。成功キャッシュ・暫定キャッシュ・原文保持を分け、キー、応答本文、生のエラーはこの記録へ含めない。ログ用の独立した有界キューが満杯なら診断を省略し、翻訳キューは消費しない。

0.7.0では、翻訳済みの文章をJAR内のJSONから照合する経路を追加した。初回実装はコード内のテストとビルドで確認し、その後2026-10-29の依頼で実クライアントによる少数例の確認に進んだ。全件のゲーム内確認は未完了で、元コーパスの採用フラグは変更していない。

## 設定と動作

0.7.7では固定辞書・照合テンプレートに、確認済み採用判断`candidate-reviewed.json`と色対応`alignment.json`を加えた。固定74,171キーに対し採用判断375件、色対応60プランを同梱する。追加データのSHA-256・サイズもマニフェストと照合し、内容はビルドIDにも反映する。

0.7.8では実機で観測したUI案内を`scripts/dictionary-observed-ui.json`に、明示的に確認した数値ファミリーを`scripts/dictionary-numeric-families.json`に保存する。原文・訳文・観測したイベントと行番号・ハッシュを検証してから生成し、未知の文を自動で一般化しない。`ordinary-tokens.json`はHealthの説明にある小文字healthの普通語判断を保持し、原文ハッシュ・UTF-16位置・全出現箇所の一致を確認する。大文字の名称や数字・記号は普通語ルールにできない。この資源のSHA-256・サイズもビルドIDとマニフェストへ含める。

F8の「確認済み本文の標準色」（`dictionaryPlainFallback`、初期値ON）は、対応表で普通の説明文・降格許可まで確認した部分に限る。数値・名前・記号や未知の英語名を含む部分は対象にしない。許可対象はchocolateyを含む1原文のitem/UI。ONでも、想定外の色範囲や名前・値の不一致を通さない。

F8 →「同梱辞書」→「試験版の同梱辞書: ON」→「保存して戻る」。設定ファイルの項目は`candidateDictionary`、初期値は`false`。この画面の保存は辞書設定だけを反映し、APIキーやHUD設定を保持する。

0.7.1からは同じ画面に「登録済みの説明を即表示」を追加した。設定項目は`dictionaryAutoDisplay`、初期値は`true`。同梱辞書がONなら、ツールチップの描画前の処理で一致した説明段落を同期的に置き換える。原文を一度表示してから非同期で切り替える方式ではない。未登録の段落は原文のまま残し、登録済み部分だけ日本語にできる。即表示のためにAPIへ送信しない。OFFなら辞書訳はGの手動翻訳時に使う。NPCの自動翻訳には影響しない。

有効なときの翻訳リクエストは、対応する説明段落やNPCの台詞を辞書、保存済みAPI訳、外部APIの順に調べる。辞書一致にはAPIキー・通信・API待ち時間は不要。不一致の翻訳には従来どおりAPI設定が必要。翻訳キー、Shiftでの原文表示を維持する。GによるAPI処理中は最初から表示できた辞書部分を残し、残りのAPI訳は説明全体が完成してからまとめて表示する。

0.7.3でバックグラウンド翻訳機能を削除した。アイテムを見ただけでAPI翻訳を予約・送信する処理はない。辞書の即表示とGによる手動翻訳を利用する。過去のキャッシュとログは保持し、キャッシュは手動翻訳時に再利用できる。旧設定の`backgroundTranslation`・`backgroundIdleSeconds`・`backgroundIntervalSeconds`は読み込み時に無視され、次回保存時に除かれる。0.7.3は依頼によりテストと実機確認を行っていない。

Ctrl＋翻訳キー・再翻訳ボタンは、辞書を迂回して原文をAPIへ再送する。そのサービスの存続中はAPIの再翻訳結果を優先して表示し、設定の再読込・再起動では辞書優先に戻る。接続テストもAPIを使う。

## 人による編集と再生成

編集元は別作業フォルダ`../skyblock-jp-dictionary/20261028/`の翻訳JSON。原文・ID・文脈・出典を保ち、対応する`ja`を直して既存のコーパス検証を行う。JAR用の生成済みJSONを直接直すと再生成で失われる。

リポジトリのルートで次を実行する。Python 3.10以上・標準ライブラリのみを使用し、APIへの送信は行わない。

```powershell
python scripts/compile_dictionary.py --source-root ../skyblock-jp-dictionary/20261028 --candidate --output src/main/resources/assets/skyblock_jp/dictionary/candidate.json --report src/main/resources/assets/skyblock_jp/dictionary/candidate.manifest.json
python -m unittest discover -s scripts/tests -p test_compile_dictionary.py -v
```

通常のビルドは同梱済みのスナップショットを使うため、元コーパスやPythonなしでも可能。`verifyBundledDictionary`がマニフェストとJSONのSHA-256・サイズ・候補フラグを検証する。手動で更新する場合は、辞書とマニフェストの両方を再生成する。

```powershell
.\gradlew.bat offlineTest build -x test
```

`offlineTest`は実API試験用のテストクラスを実行対象から除き、入力・表示コンポーネント・モック通信だけを使う。Minecraftの`runClient`は実行しない。通常の`test`は従来の実API試験の環境変数による明示的な実行方法を維持する。依存ライブラリが取得済みなら`--offline`も付けられる。

### 0.7.2での照合・表示経路の見直し

## 診断と出典

### 0.7.10の残存原文の再精査

未一致202種類は、全288観測を旧再生データから復元して追跡した。旧報告の出典配列は最大4件だったため、その配列だけで全観測を代表させない。元の物理行範囲と新しい行判定・重なる段落を比較し、単なる段落削除や分類変更を日本語化として数えない。

`TooltipMetadata`は、完全な数値形式と実際のセクションの根拠がある行だけを原文保持にする。文末へ条件や通常の説明を付けた場合は保持条件に一致しない。Combo見出しと討伐報酬の説明は翻訳対象として残す。固有名称の辞書登録も、`keep_original=true`、原文と訳文の一致、保持理由、取得証跡、限定した名称ロールを必須とし、NPCや通常の説明文をこの方法で除外しない。

`HexColorTokens`は六桁のRGB値を単一の原文の値として保護する。A〜Fの大文字・小文字は同じ色として照合し、表示は実際の原文の綴りとStyleを使う。色値の変更・追加・削除は拒否し、通常の数量検証からRGB内の数字を除く場合も、先にRGB全体の一致を検証する。数字の番号ラベルの既存の文法は変更しない。

Fire Veilの数値テンプレートは固定5秒・毎秒ダメージ・対象・全文を限定する。変更されていない採用済み訳3組と保存済みゲーム原文をハッシュ・出典ID付きで照合し、値だけを受け渡す。保存済み記録には新しい実機時刻や実際の色情報を付与しない。符号・省略単位・別の時間や対象へは一般化しない。

原文の生の`§`書式は、翻訳用の数値や名称を保護する前にStyleへ変換する。標準ASCIIコードだけを認識し、未知コードや末尾の`§`は保持。色コードの強調解除、継承StyleへのRESET、native runごとの独立した範囲をMinecraft 26.2の実装に合わせる。

復元保留11件は、確認済みの英語名称の形と、原文・訳文・ハッシュ・出典IDに限定した対応表で解消した。Hot Chocolateも通常の味の形容詞`chocolatey`を日本語へ対応付け、平文への退避を不要にする。未確定のLeechの割合を推測して補う処理は追加しない。

### 0.7.9の未収録補完と本文の派生

編集元の`scripts/dictionary-observed-text.json`は、実機ログ、過去のツールチップ記録、再抽出したWiki原文を区別する。`en`と原文ハッシュ、話者・チャンネル・役割、原文行とそのハッシュは取得根拠。`ja`・承認・理由は訳の判断で、原本翻訳パックの採用フラグとは別に管理する。Wikiは固定版・取得ファイルのハッシュ・抽出元全文・対象行も検査する。記録に時刻や画面がない場合は捏造せず、保存済みスナップショットとレコード位置を用いる。NPC本文には話者を必須とし、プレイヤーチャットへ転用しない。

`scripts/dictionary-skill-bodies.json`は、元の`common/skill_unlock`の能力名と本文の分離を確認した507組を保持する。元の原文・訳文・ラベル・区切り・出典ID・ハッシュを検査し、元の組が変わった場合は生成を止める。派生先はUI説明だけで、common辞書全体の適用先は変更しない。

`scripts/dictionary-npc-phone-lines.json`は、出典のConditionにAbiphone対応が明記されたDeanの18行を電話記号付きで保持する。元の採用訳、話者、原文、グループ・行ID、条件、取得資料のハッシュをコンパイル時に検査する。電話記号を一律に削除した照合や全NPCへの自動展開は行わない。既存の電話専用訳とプレイヤー名を含む文はそのまま保持する。

`Level {v0} Rewards:`のUIテンプレートは、正規のRoman数字I〜Cだけを許可する。他のRoman数字テンプレートの範囲は変更しない。本文色の判定は、保護された名称・数値・記号を除く実際の本文文字を根拠にする。灰色・白色の本文に加え斜体の説明も扱い、未知の別色強調を勝手に本文色へ統合しない。

新たな訳と原本の候補が競合した場合も、隔離情報を保持したまま、原文・全候補・出典のハッシュに結び付いた`dictionary-reviewed.json`の判断で採用する。普通語の誤保護を直す場合は、確認した語と位置を原文ごとに記録する。原文や競合候補が変われば自動採用しない。

コマンド例の`<name>`・`<username>`・`<id>`は、スラッシュコマンドに続く既知の引数表記として検査する。番号ラベルの`#`も数値に続く形だけを認める。安全性の検査でだけ識別し、検索キー・訳文・色復元で括弧や`#`を削らない。引数を別の語へ変えた訳は生成・表示の両方で拒否する。

原文取得側の修正は、保存済みの保留7,010イベントを調べ、コマンド引数を含む5種類のUIページと、見出しの`colspan`末尾が崩れた会話表へ適用した。本文の列数や条件が曖昧な表、プレイヤー名が入る台詞などの取得・採用条件は引き続き検査する。

### 0.7.8の実機フィードバック

能力見出しの分離は、段落境界・タイトル形状・直後の効果文を併用する。Doubles/Triples等も効果文として認識し、Teleport Savvyのように動詞を含む曖昧な名称だけは、読み込み済み辞書が`keepOriginal`かつ`item/label/`由来と確認できる場合に分離する。単なるTitle CaseやGain Health等の説明文を根拠なく捨てない。

照合理由ログON時は、NPCの辞書不一致を`npc-dictionary-decisions.jsonl`へ保存する。`stage`と`reason`が辞書側の停止理由、`fallbackAction=API_OFF_STOP`はAPI設定による停止。`API_FALLBACK_ALLOWED`はAPI経路へ進めることだけを表し、実際のAPI送信を保証しない。原文・話者・受信時の前会話・辞書ビルドとハッシュ、復元失敗の候補や個数、元の色を追える。重複排除は文脈とAPI方針を含め、長い文章・色断片は上限と完全性フラグを付ける。診断OFFや閉じたサービスでは出力せず、従来の有限キュー・伏せ字・2MBローテーションを利用する。

### 0.7.7の採用判断・文脈・対応表

競合232原文・話者組を全件再精査し、225組を標準訳／自然な共通訳、3組を画面条件付きにした。Strong、Competitive、Check Your Produce、Tyashoi Alchemistの比喩を含む台詞の4組（5スコープキー）は保留。条件を得られない場合に、別の画面の訳やWiki上の条件を推測して適用しない。

採用判断は原文と候補群のハッシュ・出典・承認・適用先を保持する。原文や候補が変わった判断、条件が不足する判断、相反する判断では従来の隔離を維持する。数字・記号・名前の不変条件も検査する。GUIの画面・スロット等と、NPCの前の台詞は、実際に観測した値だけを辞書へ渡す。

NPCの文脈はComponent参照と受信ごとの識別子で管理し、同じ文章で上書きしない。受信イベントとGUI挿入には別の前会話履歴を持ち、他modによるコピーで二重に進めない。設定による履歴再構成では元の対応だけを移す。知らないコピー・変更された本文・期限切れ・別の接続の文脈は補わない。辞書の判断キャッシュとアイテム／UIのAPI状態は文脈ごとに分離する。

色対応は固定のRGBではなく、原文の範囲と訳文の範囲・意味スロットを記録する。対応表のハッシュと範囲、名前・数値・記号、重複や欠落を検査し、現在のComponentの色と装飾を使う。通常本文の色は先頭の色付き名前から決めず、既存のgray/weighted方針で取得する。新しい色や未知の名前を単純に無視して表示しない。

照合理由には`dictionaryBuildId`、`sourceSha256`、`normalizedSourceSha256`、`sourceHashFormat`、`targetSha256`、`targetCandidate`、`dictionaryContext`と色対応の詳細を保存する。ハッシュは原文生テキストと正規化後を区別する。元の色付き行には`originalStyledLinesComplete`と採取glyph数を付ける。対応表を作る際は、途中までの記録を完全な原文として扱わない。

### 0.7.6の照合・色復元・状態管理

最終検証はJava356件・Python27件が成功。固定辞書の全74,171キー、テンプレート554件、実ログの色復元失敗11例を検査した。固定キーのうち専用辞書とcommonの競合12件、隔離キーと正規化上で同じになる4件は、対応する実データと理由を確認して拒否をテストする。全件の平文・灰色変換と、実際の色付き11例の再生は区別している。クライアント起動・実API通信・導入済みJARの差し替えは行っていない。

取得元の`item`／`ui`と実行時の適用先を分離した。元資料の`slot_description`はitemにも、アイテムのdescription／ability_body／flavor／instruction／requirement／list_entryはUIにも展開する。NPC・system・プレイヤーチャットへの展開はしない。旧53,420キーから20,917キーを追加し、競合が判明した既存166キーは隔離した。保持したキーの訳文と原本JSONは変更していない。item／UIとcommonの間の競合も実行時に拒否する。

隔離した363キーは`blocked_keys`にも保存する。エントリーを削除するだけでは共通辞書への迂回で再び採用されるため、完全一致・正規化・別名・テンプレート照合より前に隔離キーを確認する。照合リソースが読めない場合でも、主辞書内の隔離情報を維持する。

変数テンプレートは原文・訳文それぞれの範囲を`Binding`として色復元へ渡す。先頭が変数のテンプレートも検索できる。Farming Fortune／Mining Fortune／Mining Speed／Intelligence／Strength／Defenseの確認済みアイコン差は、名前との隣接を条件に照合し、表示には原文のアイコンを戻す。数値・名前・色が一意に対応しない場合の拒否は維持する。

ツールチップの手動翻訳キーは、数値ステータスや末尾の他mod情報を含めず、実アイテムID・名前・分類・翻訳段落から作る。表示元の照合では本文と書式のスナップショットを使い、コピーや末尾への追記を許可しつつ、本文の変更・複数の出所が一致するケースを拒否する。Minecraftが実際に実行する描画コールバックだけを観測し、候補として渡された後に破棄されたツールチップはGの対象にしない。

API成功・暫定訳・期限付き失敗を区別し、失敗したNPCの再試行と、キャッシュから消えた結果の「翻訳中」表示を修正した。API回答の補正では修正案を検証し、正常な元回答を壊す案を採用しない。`translation-repairs.jsonl`には原回答・修正案・採用結果・修正案の検証理由を記録する。

辞書生成では出力・照合リソース・マニフェストが同じパスにならないことを事前に確認し、一時ファイルから置換する。照合規則だけの変更でもビルドIDが変わり、固定辞書と照合リソースを共に識別できる。3ファイルまとめての置換が単一の原子的操作になるわけではないため、中断時の混在はビルドのハッシュ検査で拒否する。

0.7.5のF8設定「外部API翻訳」（`apiTranslation`、初期値ON）は、保存すると外部API通信と過去のAPIキャッシュの利用をまとめて止める。OFF中も同梱辞書・ローカル定型訳を使い、辞書未収録は原文を残す。Ctrl+Gと接続テストも送信しない。APIキー・モデル・保存済みキャッシュは保持し、ONへ戻せる。旧設定に項目がない場合はONを維持する。

OFF中の手動Gは辞書だけを照合し、未登録の説明でPENDINGに留まらない。表示ログの`apiState=API_DISABLED`／`apiTranslationEnabled=false`と、`dictionaryStage`・`reason`の辞書側の結果を分ける。手動操作でAPIへ進めなかった箇所は`stopStage=POLICY`／`displayReason=API_TRANSLATION_DISABLED`、Ctrl+Gの受付は`RETRANSLATION/API_DISABLED`に記録する。NPCやチャットの未知文は翻訳結果として重複表示せず、手動操作の場合だけOFFの案内を出す。設定切替前に既に送信された通信を取り消せる保証はないが、閉じたサービスの遅延結果は新設定の表示へ適用しない。

0.7.4では行を結合する前に、名称・数値ステータス・価格／素材・能力見出し・操作文・説明・進捗・デバッグ等の役割を決める。分類はスロット観測（PLAYER/CONTAINER/UNKNOWN）、ツールチップ種別（ITEM/UI/UNKNOWN）、段落の辞書チャンネルを別々に保持する。スロットが取れないことをPLAYERの証拠にはせず、実ID・レア度・ペット等を優先し、店舗名に依存しない操作文や厳密な操作ラベルとアイコンの組み合わせも使う。実アイテムの説明はitem、併記された操作案内はuiとして別段落にする。

「照合理由ログ」ON時の`translation-display.jsonl`（schemaVersion=2）には、`tooltipClassification`の根拠、`lineDecisions`の役割・KEEP/TRANSLATE/JOIN・理由・所属段落、`paragraphDecisions`のチャンネル・元行番号・`dictionaryStage`・`stopStage`・`dictionaryDetails`・`apiState`を保存する。色復元に失敗した場合は、対応しなかった断片、元のRGB／書式、候補数、数値や名称の不足・余剰、アンカー不一致の段階も分かる。原文保持（意図した除外）と辞書の未登録、復元失敗、全段落待機、API失敗を区別する。

別ファイル`translation-pipeline.jsonl`には、ELIGIBILITY（設定OFF・対象サーバー外・Shift等）、OBSERVATION（表示されたがItemTooltipCallbackと対応しなかった文章）、MANUAL_INPUT（G受付・入力欄フォーカス・古いホバー等）、RETRANSLATION（再翻訳対象なし・既存要求待ち等）、REQUEST_DISPATCH／REQUEST_COMPLETE（段落要求の前後）を記録する。`session`と`tooltipId`、要求内の`paragraphId`で表示ログと関連付ける。手動操作・要求イベントは個々に記録し、同じ画面状態の連続フレームだけ重複を省く。両ファイルは従来と同じ2MBローテーション、有限キュー、APIキーの伏せ字を使う。

旧0.7.3のログは行ごとの判定根拠を含まないため、後から断定できない分類もある。新ログのslot/evidenceがない原文再生では、仮定した位置情報を明示し、実クライアントの表示結果と区別する。

OBSERVATIONは他modのコピー・追記後の表示を含むため、`sourceSnapshotKind=UNMATCHED_DISPLAY`と`observedDisplayLines`へ記録し、原文の`originalLines`とは区別する。このイベントだけでは原文取得の失敗や辞書未登録とは断定しない。

実機確認により、一覧の末尾、数値の合計、修飾付きCost見出し、Passive／Active見出しも行の役割として分離した。未操作のツールチップの即表示は、別のツールチップで同じ操作文を再翻訳しても辞書を使う。明示的に手動翻訳した対象ではAPIの優先表示を維持する。

起動時のmodログには読込結果・ビルドID・有効キー数を出す。辞書による翻訳のリクエストは`config/skyblock_jp/dictionary-translations.jsonl`に原文・訳文・出典ID・辞書ビルドIDを非同期記録する。描画のたびにログは書かない。APIを使った文は従来のログに記録する。
